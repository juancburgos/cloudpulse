# API contract

Base URL (production): `https://api.juancarlosburgosautor.com`
Interactive docs: `/docs` (Swagger UI) · `/redoc` (ReDoc) · machine-readable schema at `/openapi.json`

All responses are `application/json`. CORS is open on `GET`/`POST` because this is a public demo API with no
credentials, no cookies and no personal data.

---

## `GET /healthz`

Cheap dependency probe for containers, load balancers and uptime monitors. Runs a single `SELECT 1`.

**200**

```json
{ "status": "ok", "db": "up", "version": "1.0.0", "uptime_s": 5187 }
```

| Field | Type | Notes |
|---|---|---|
| `status` | `ok` \| `degraded` | `degraded` when the database probe fails |
| `db` | `up` \| `down` | Dependency state |
| `version` | string | Injected at build time (`APP_VERSION`) |
| `uptime_s` | integer | Seconds since the process started |

> Conventions: the endpoint answers **200 even when degraded** — the degradation is in the body, so a reachable
> but partially broken instance is distinguishable from a dead one. Monitors should alert on the `db` field,
> not only on the status code (see ADR-0004).

## `GET /api/v1/status`

Everything the app renders in one round trip: identity, server metadata and database health.

**200**

```json
{
  "app": "CloudPulse",
  "version": "1.0.0",
  "status": "ok",
  "server": {
    "hostname": "5a9832cbd635",
    "region": "us-east-1",
    "platform": "Linux 6.8.0-137-generic",
    "python": "3.12.14",
    "started_at": "2026-09-09T22:13:28.361804+00:00",
    "uptime_s": 5187
  },
  "database": {
    "status": "up",
    "latency_ms": 12.4,
    "total_pings": 10,
    "last_ping_at": "2026-09-09T22:33:41.241192+00:00"
  },
  "time": "2026-09-09T23:40:02.904829+00:00"
}
```

On a database failure the same shape is returned with `"status":"degraded"`, `"database.status":"down"` and
`null` for `latency_ms`, `total_pings` and `last_ping_at` — the client is expected to render placeholders, not
to crash.

## `POST /api/v1/ping`

Records a ping. This is the write path: it proves that persistence is real.

**Request** — no body required. The `User-Agent` header is stored (truncated to 120 chars) as the `source`.

```bash
curl -s -X POST https://api.juancarlosburgosautor.com/api/v1/ping
```

**201**

```json
{
  "ok": true,
  "ping_id": "597c24c2",
  "db_row_id": 10,
  "created_at": "2026-09-09T22:33:41.241192+00:00",
  "total_pings": 10,
  "server_version": "1.0.0",
  "region": "us-east-1"
}
```

| Field | Notes |
|---|---|
| `ping_id` | Short correlation id generated by the API (for logs) |
| `db_row_id` | Primary key of the inserted row — the actual persisted proof |
| `total_pings` | Count after the insert, so one call proves write **and** read |

**500** — `{"status":"error","detail":"internal_error"}` when the database is unavailable.

**429** — rate limited. The endpoint is public and every call costs a row, so it is metered per client
address (`RATE_LIMIT_MAX` per `RATE_LIMIT_WINDOW_S`, default 20 per 60 s — see ADR-0005):

```json
{ "status": "throttled", "detail": "rate_limit_exceeded", "limit": 20, "window_s": 60 }
```

The response carries `Retry-After` (seconds). The client address is read from the right-most
`X-Forwarded-For` entry, which is the one Caddy vouches for; a caller-supplied prefix is ignored, so
inventing a new address per request does not buy a new quota.

## `GET /api/v1/pings?limit=10`

Most recent pings, newest first. `limit` is clamped to `1..50`.

```json
{ "pings": [ { "id": 10, "source": "okhttp/4.12.0", "created_at": "2026-09-09T22:33:41.241192+00:00" } ] }
```

## Error semantics

| Status | When | Body |
|---|---|---|
| 200 | Success, including *degraded* dependency state | `{"status": "ok" \| "degraded", ...}` |
| 201 | Ping created | `{"ok": true, ...}` |
| 404 | Unknown path | FastAPI default |
| 422 | Invalid query parameter (e.g. `limit=abc`) | FastAPI validation detail |
| 500 | Unhandled server error (typically database unreachable) | `{"status":"error","detail":"internal_error"}` |

## Versioning

The URL carries the major version (`/api/v1/...`). Additive fields are non-breaking; removing or renaming a
field requires `/api/v2/`. `/healthz` is intentionally unversioned: it is an operational contract.
